## 1. Usage in responses

### Is usage always on?

Yes. `usage: { include: true }` and `stream_options: { include_usage: true }` are **deprecated and have no effect**; full usage is in every response. Non-streaming: in the body. Streaming: once, in the **last chunk before `[DONE]`**, and unlike OpenAI's spec that chunk has a non-empty `choices` array (one content-free delta repeating `finish_reason`). (Usage accounting, API overview.)

### Chat Completions `usage` (OpenAPI `ChatUsage`)

### Tokens: native or normalized?

**Native.** The current docs say twice that response token counts "are calculated using the model's native tokenizer" and that "credit usage and model pricing are based on these native token counts". (The older GPT-4o-normalized counting is gone from the docs; the model object still has `architecture.tokenizer` as a label: GPT, Claude, Gemini, Other...) One wrinkle: OpenRouter's export docs call the generation record's `tokens_prompt` / `tokens_completion` "OpenRouter's own token estimates, not the provider's token counters", while `native_tokens_*` are the provider's counters. Which of them match `usage` in the response is **unverified**.

A `usage_is_estimated` flag exists in Broadcast exports: when the provider returns no usage (e.g. a cancelled or interrupted stream), OpenRouter falls back to its own quantities. The response `usage` has no such flag.

### `GET /api/v1/generation?id=gen-...` (needs a key; live call returns 401 without one)

Returns `data` with (OpenAPI `GenerationResponse`, all keys required unless noted):

| Group                            | Fields                                                                                                                                                                                                                                                                                                      |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cost                             | `total_cost` (USD), `usage` (USD), `cache_discount` (number, null; negative for cache writes on Anthropic, positive for reads), `upstream_inference_cost` (BYOK only; "0 or null" otherwise), `is_byok`                                                                                                     |
| Tokens (normalized-or-estimated) | `tokens_prompt`, `tokens_completion`                                                                                                                                                                                                                                                                        |
| Tokens (provider-reported)       | `native_tokens_prompt`, `native_tokens_completion`, `native_tokens_reasoning`, `native_tokens_cached`, `native_tokens_completion_images`                                                                                                                                                                    |
| Routing                          | `provider_name`, `model`, `upstream_id`, `provider_responses[]` (including fallback attempts), `router`, `service_tier`, `data_region`, `request_id`                                                                                                                                                        |
| Timing                           | `latency` (total ms), `generation_time` (ms), `moderation_latency`                                                                                                                                                                                                                                          |
| Other                            | `finish_reason`, `native_finish_reason`, `streamed`, `cancelled`, `api_type`, `num_search_results`, `num_fetches`, `num_media_prompt`, `num_input_audio_prompt`, `num_media_completion`, `web_search_engine`, `external_user`, `session_id`, `preset_id`, `response_cache_source_id`, workspace and app ids |

Differences from the response `usage`:

- **No cache-write token count** (`native_tokens_cached` only), no `audio` / `video` split, no `cost_details` split, no `server_tool_use`.
- Adds `cache_discount`, `provider_name`, `latency`, `generation_time`, `upstream_id` and the per-attempt `provider_responses`.
- It is a lookup after the fact (the docs call it useful "for auditing historical usage"); how soon after a response the record exists is **unverified**.
- Content (prompt / completion) is a separate call, `GET /generation/content?id=` (needs a management-style permission; may be refused).
- Activity can also be exported/streamed through Broadcast and the Activity export, which add `billed_service_tier`, `usage_is_estimated`, cache and native-tool counters.

## 2. Cost

### What `cost` is

- **Unit: USD**, even though the docs call them "credits" (1 credit = 1 USD; the generation record says "Total cost of the generation in USD"). Number, not string.
- It is the **amount deducted from your OpenRouter balance** for this request ("the total amount charged to your account").
- **No markup on inference.** "Inference is billed at each provider's list price on every plan." OpenRouter's fee is taken when buying credits (5.5% Standard, 8% Business, crypto extra), never per request. So `cost` is the provider's price for the endpoint that served the request.
- Cache reads are billed at the endpoint's cache-read rate and cache writes at its write rate, so `cost` is already the net of cache savings. `cache_discount` (generation record only) is the saving vs. uncached.

### BYOK

| Case                           | `cost`                                                                     | `cost_details.upstream_inference_cost` |
| ------------------------------ | -------------------------------------------------------------------------- | -------------------------------------- |
| Normal (OpenRouter credits)    | Provider list price                                                        | 0 or null                              |
| BYOK within the free allowance | 0 (the provider bills you directly)                                        | Provider's estimated inference cost    |
| BYOK above the allowance       | OpenRouter's fee: **5% of what the same request would cost at list price** | Provider's estimated inference cost    |

The allowance on Standard and Business is $25,000 of list-price inference per month (the BYOK docs page has the numbers blanked by a template; the pricing page states them). So for a BYOK request, `cost` alone **understates** the real spend; real spend is `upstream_inference_cost` + `cost`. The "upstream cost" is OpenRouter's estimate from the usage it saw, not the provider's invoice. The Generation endpoint says `upstream_inference_cost` is "only available for BYOK" requests.

### What is and is not in `cost`

| Item                                              | In `cost`?                                                   | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Input, output, reasoning tokens                   | Yes                                                          | Reasoning is in `completion_tokens`, billed as output. Models with a separate `internal_reasoning` price: 31 of 458, and 30 of them price it the same as completion.                                                                                                                                                                                                                                                                                                          |
| Cache read / write                                | Yes                                                          | Rates per endpoint (below). Anthropic: write 1.25x input (5 min) or 2x (1 h); reads 0.1x. OpenAI GPT-5.6+: writes 1.25x input even with automatic caching. Gemini: write includes storage time.                                                                                                                                                                                                                                                                               |
| Service tier (flex / priority / fast / ultrafast) | Yes, at the tier endpoint's rate                             | Each tier is its own endpoint with its own price (gpt-6.1-sol: flex 0.5x, default 1x, fast 2x, ultrafast 6x).                                                                                                                                                                                                                                                                                                                                                                 |
| Long-context surcharge                            | Yes                                                          | Endpoint `pricing.overrides` by `min_prompt_tokens`.                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Time-of-day pricing                               | Yes                                                          | `overrides` with `utc_start` / `utc_end` / `utc_days` (3 models today).                                                                                                                                                                                                                                                                                                                                                                                                       |
| Metered server tools (shell sandbox)              | Yes                                                          | `cost_details.server_tool_cost` "matches the billed amount exactly".                                                                                                                                                                                                                                                                                                                                                                                                          |
| Web search (plugin, server tool)                  | **Probably yes, unverified**                                 | Priced per request on top of tokens: Exa $0.007 (auto) to $0.015 (deep reasoning) per request, $0.001 per result above 10; Parallel $0.001 to $0.005; Perplexity $0.005; Firecrawl uses your Firecrawl credits (no OpenRouter charge); native search is passed through from the provider. Catalog `pricing.web_search` is $0.0025 to $0.018 per search (182 models). The docs never say these appear inside `usage.cost`; they say "in addition to standard LLM token costs". |
| Per-request fee (`pricing.request`)               | n/a                                                          | The field is documented but **no model in the live list sets it** (0 of 458).                                                                                                                                                                                                                                                                                                                                                                                                 |
| Image input                                       | Yes, `pricing.image` per image (30 models), or `image_token` | Unit is USD per input image.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Image / audio output                              | Yes                                                          | `image_output`, `audio_output`, `audio` prices; token counts for them are only partly in `usage`.                                                                                                                                                                                                                                                                                                                                                                             |
| Batch API                                         | Yes, usually 0.5x                                            | 76 `:batch` entries; 69 of 76 priced at exactly half of the base entry, the other 7 differ (0.37x to 5.7x).                                                                                                                                                                                                                                                                                                                                                                   |
| Response-cache hit                                | **Zero**                                                     | "No billing (all billable usage counters are reported as 0)".                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Failed or fallback attempts                       | **Not billed**                                               | "An attempt that errors is not charged for its model tokens." Zero Completion Insurance also covers empty responses.                                                                                                                                                                                                                                                                                                                                                          |
| Free models                                       | 0                                                            | `:free` entries have prices of "0" and their own limits; web search on them still costs.                                                                                                                                                                                                                                                                                                                                                                                      |
| OpenRouter's credit-purchase fee                  | No                                                           | Charged at top-up.                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

So, can we use `usage.cost` as `cost.total`? **For non-BYOK requests, yes**: it is the authoritative, already-routed price and includes everything above except possibly web search (to confirm by probe). For BYOK it is the fee only, so a gateway that wants "what did this call cost me" needs to add `upstream_inference_cost` (or report both). Reported `cost` cannot be split into input / output / cache buckets (only the upstream prompt-vs-completion split, which is for upstream cost).

Cancelled streams: if the client disconnects and the upstream can be aborted, billing is for the output delivered; if it cannot be aborted, OpenRouter bills what was delivered while the provider may keep generating (matters for BYOK).

## 3. The model catalog: `GET /api/v1/models`

Public, no key. Cached at the edge (`cache-control: public, max-age=120, stale-while-revalidate=3600`); ~0.2 to 0.35 s from here. Raw copy: `scratchpad/openrouter/catalog/models.json`. Script: `scratchpad/openrouter/scripts/analyze.js`, `analyze2.js`.

### Query parameters

| Parameter                                                 | Effect                                                                                                                                                        |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `output_modalities`                                       | Default is **text-output only**. `text,image`, `embeddings`, `speech`, `transcription`, `video`, `rerank`, `decisions`, or `all`.                             |
| `supported_parameters`                                    | Filter, e.g. `tools`.                                                                                                                                         |
| `sort`                                                    | `pricing-low-to-high`, `pricing-high-to-low`, `context-high-to-low`, `throughput-high-to-low`, `latency-low-to-high`, `most-popular`, `top-weekly`, `newest`. |
| `offset`, `limit`                                         | Opt-in pagination (default 500, max 1000). Without them: everything and `links.next: null`.                                                                   |
| `use_rss=true`                                            | RSS feed of new models.                                                                                                                                       |
| `/models/count`, `/model/{author}/{slug}`, `/models/user` | Count (458), one model (resolves aliases and variants), the key's own filtered list (401 without a key).                                                      |

## 4. Does endpoint pricing differ from model-level pricing?

**Yes.** The model-level `pricing` is "pricing from the top provider" (Models guide); in the live data it equals one endpoint's price for all 431 priced models. A request can be served by any endpoint, by default through **price-weighted load balancing** ("weighted by inverse square of the price" among providers without recent outages), so the price you pay is the served endpoint's price, not necessarily the model-level one. Sticky routing keeps a conversation on one provider for 10 minutes once caching is in use, unless `provider.order` is set.

What routing can and cannot reach (docs, and checked against the data):

- Regional endpoints (`/us`, `/eu`, `/europe`, `us-east-1`...) carry a premium (about +10%) and are **skipped by the global API unless you target them** with `provider.order` / `only`.
- Service-tier endpoints (`flex`, `priority`/`fast`, `ultrafast`) join the pool only through `:floor` / `:nitro` or an explicit `service_tier`.
- `provider.sort`, `order`, `only`, `ignore`, `quantizations`, `max_price` change the pool; `require_parameters` filters on per-endpoint `supported_parameters`.

Quantified on the 164 models that have at least two default-routable endpoints (tier and region endpoints excluded), at 10k input / 1k output tokens with the model-level price as the static estimate (`scripts/endpoint-spread-default.js`; 100k / 2k gives the same picture):

| Measure                                                                                   | Result                                 |
| ----------------------------------------------------------------------------------------- | -------------------------------------- |
| Models with exactly one default endpoint (static price is exact)                          | 266 of 430 (62%)                       |
| Multi-endpoint models whose max / min endpoint cost differs by 5% or more                 | 44%                                    |
| ... by 1.5x or more                                                                       | 29%                                    |
| ... by 2x or more                                                                         | 21%                                    |
| ... by 5x or more                                                                         | 5% (max 16.6x: deepseek-v4-flash-0731) |

## 5. Stability of model ids, deprecation and expiry

- **Ids are not guaranteed forever, but they are conservative.** Old ids stay listed (`openai/gpt-4`, `gpt-3.5-turbo-0613`, `gpt-4o-2024-05-13`, ... all present; 152 models are over a year old). `canonical_slug` is the permanent slug, but it is not routable via `/model/` (404 when tried). The docs claim aliases redirect (`anthropic/claude-3-5-sonnet` to `claude-3.5-sonnet`), yet that lookup is **404 today** because the target no longer exists: alias redirects die with the model.
- **Floating ids exist on purpose:** `~vendor/family-latest` (18 today; `alias_target` shows the target, e.g. `~openai/gpt-sol-latest` to `openai/gpt-6.1-sol`) and routers (`openrouter/auto`, `free`, `fusion`, `pareto-code`, `bodybuilder`, with `-1` prices). Do not cache price or capability by such an id. Response `model` shows what actually served.
- **Expiry signal:** `expiration_date` on the model (and the endpoint listing carries the date by endpoint deprecation). 18 models have one today, from 2026-10-20 (gemini-2.5-pro / flash / flash-lite, 8 days away) through 2026-12-31 (glm-4.5, glm-4.7); none is past due, so the list drops models after the date. After removal, requests give 404 "no endpoints for this model found" (pricing FAQ). The field is documented as "may be removed", a date only, no time zone.
- Notices: email alerts for "model deprecation" and "price drop" for models in recent use (account setting).
- **Price changes are silent for callers:** "If the pricing changes, we will continue to route to the model and it will serve your requests. But, you will be charged at the new rate." So a snapshot can go stale without any id change.
- **New models arrive fast:** 44 of 458 models were added in the last 30 days (about 10% a month), including whole new families with their own prices.
- Catalog variants (`:free`, `:batch`) can appear and disappear independently of the base model; a missing variant gives 404 on `/model/...`, empty `endpoints` on `/endpoints`, and a failure on inference. Routing variants never appear in the list.

## Implications for our gateway

### Reported cost vs estimated cost

| Question                        | Finding                                                                                                                                                                             | Consequence                                                                  |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Is reported cost authoritative? | Yes for non-BYOK: provider list price at the endpoint that served, tiers, long context, cache, discounts, retries not billed.                                                       | Use it as `cost.total`.                                                      |
| Can an estimate match it?       | Only if we know the serving endpoint, tier and time; the response does not name them reliably (`provider` field and `X-Provider-Name` unverified; `openrouter_metadata` is opt-in). | A catalog estimate is a guess for ~40% of models.                            |
| Can reported cost fill buckets? | No: no input / output / cache split of `cost`.                                                                                                                                      | `cost.total` only; leave `input`, `output`, `cacheRead`, `cacheWrite` unset. |
| BYOK                            | `cost` is only the fee.                                                                                                                                                             | Add `upstream_inference_cost` for real spend; surface `is_byok`.             |
| Our `estimateCost`              | Needs the 1h write split (`details.cacheWrite1h`), which OpenRouter's usage does not give (only `cache_write_tokens`).                                                              | It cannot price Anthropic writes exactly via OpenRouter anyway.              |

### Options for the catalog (D11)

| Option                             | What it is                                                                                                                    | For                                                                                             | Against                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. Static generated snapshot**   | A script fetches `/models`, writes `catalog/openrouter.ts` like the other providers.                                          | Matches our pattern, offline, typed `KnownModelId<'openrouter'>` autocomplete, no runtime cost. | 433 models. Source size is about 100 KB at about 230 bytes per entry (full pricing; ids alone are 12 KB, compact JSON 66 KB / 10 KB gzip). Stale in weeks: about 10% of models are new each month, 18 expire within 80 days, prices change silently. Price is endpoint-dependent, so an estimate from it is wrong for open-weight models. Needs a release to refresh (which D11 says should not be needed for new models). |
| **B. Fetched at runtime**          | The gateway or SDK GETs `/models` (public, 79 KB gzipped, edge-cached 2 min) and caches it (Worker cache / KV / per isolate). | Always current: expirations, new ids, prices.                                                   | Async lookup where `estimateCost` is synchronous today; a cold-start fetch; a network dependency on a non-critical path; still model-level price, so no better at endpoint-level accuracy.                                                                                                                                                                                                                                 |
| **C. None; rely on reported cost** | Catalog is ids and metadata only (or absent); `cost.total` always from `usage.cost`.                                          | Exact money, zero staleness, no maintenance, honest when routing varies.                        | No pre-flight estimate; no cost when `cost` is missing; autocomplete is smaller.                                                                                                                                                                                                                                                                                                                                           |

**Recommendation:** C for cost, plus a small version of A for autocomplete / metadata.

1. **Cost: take `usage.cost` as `cost.total`** whenever it is present and the request was not BYOK. Never run `estimateCost` for OpenRouter. When `cost` is absent or null, omit the cost (as D15 already does for unknown models). For BYOK, report `cost.total` as `upstream_inference_cost + cost` or, safer, keep `cost.total` = reported `cost` and put the upstream amount in `native`; decide once and document it. Mark the source so callers can tell estimated from reported (a `cost.source: 'reported' | 'estimated'` or a `native` field), because D15 currently says "estimated cost".
2. **Catalog: a generated snapshot of metadata only** (id, name, context, max output, input modalities, tools / reasoning / structured-output flags, `expiration_date`), with the base price kept as `pricing` marked indicative, or dropped. The generator maps `prompt`, `completion`, `input_cache_read`, `input_cache_write(_1h)` and `min_prompt_tokens` overrides straight onto `ModelPricing`. Skip `~` aliases and `-1` price routers, `:batch` entries (different billing path), and time-window overrides. Keep it model-id typed as `KnownModelId` with `(string & {})` so any other id works (D11). Do not include a price in an estimate path.
3. **Do not fail on unknown ids**; OpenRouter accepts ids we have never seen, plus `:nitro` / `:floor` / `:exacto` suffixes that are never listed. Resolve metadata by dropping routing variants and keeping catalog variants (their documented rule). If we ever offer a live lookup, `GET /api/v1/model/{id}` already does it server-side.
4. An optional later feature: `catalog.fetch()` (option B) for tooling and pre-flight budgets, outside the response path.

### Mapping OpenRouter usage onto our `Usage`

| Our field                     | Chat Completions                                                                                                        | Responses                                 |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `totalInput`                  | `prompt_tokens`                                                                                                         | `input_tokens`                            |
| `cacheRead`                   | `prompt_tokens_details.cached_tokens`                                                                                   | `input_tokens_details.cached_tokens`      |
| `cacheWrite`                  | `prompt_tokens_details.cache_write_tokens` (omit if absent; zero only if reported)                                      | `input_tokens_details.cache_write_tokens` |
| `input`                       | `totalInput - cacheRead - cacheWrite` (assumes both are inside `prompt_tokens`; verify)                                 | same                                      |
| `output`                      | `completion_tokens` (includes reasoning)                                                                                | `output_tokens`                           |
| `reasoning`                   | `completion_tokens_details.reasoning_tokens` (part of `output`)                                                         | `output_tokens_details.reasoning_tokens`  |
| `cost.total`                  | `cost` (see BYOK note)                                                                                                  | `cost`                                    |

Notes:

- `cacheWrite` is the total for every TTL (as in our contract); OpenRouter gives no TTL split, so no `cacheWrite1h` here.
- Anthropic models through OpenRouter: if `cache_write_tokens` is omitted when there is no explicit caching, keep it omitted, not 0.
- Free and response-cache hits: usage counters are 0 and `cost` 0; that is a known zero.
- Failed attempts and fallbacks are not billed; a failed request has no usage to attach to `LlmError` (D14), unless a mid-stream failure arrives with partial usage (probe).
- The serving provider is needed for attribution and debugging: capture `provider` from the stream chunk, `X-Provider-Name`, or `openrouter_metadata`, and `X-Generation-Id` for later `/generation` lookups.
