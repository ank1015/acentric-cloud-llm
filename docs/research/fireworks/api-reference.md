# Fireworks Responses API: reference research

> **Corrected by live calls (2026-10-11, [live-shapes.md](live-shapes.md)):**
> a `store: false` response does have an `id` (it cannot be retrieved or
> chained on); usage is `input_tokens` / `output_tokens` /
> `input_tokens_details.cached_tokens`, not `prompt_tokens`; instructions and
> tools are not inherited through `previous_response_id`; an unknown or
> unstored previous response is `404 {"detail":"Previous response not found"}`;
> `input_file` parts are dropped without an error; `service_tier` and unknown
> fields are accepted and ignored; `item_reference` works. See
> [../../providers/fireworks.md](../../providers/fireworks.md) for what we rely on.

Researched 2026-10-11 from the current docs. No API calls were made; anything the docs do not state is marked "not documented".

**Important caveat on the sources.** The Guide is clearly newer than the API reference. The Guide's "Compatibility with OpenAI" section lists `background`, `include`, `top_logprobs` and `prompt_cache_key` as supported request fields, and describes `queued`, `cancelling`, a cancel endpoint, `reasoning.effort`, `text.format`, `web_search`, and Codex `namespace` tools. None of these appear in the Spec or Create ref schema (which has 20 request properties and says only that `tools` is "A list of MCP tools"). The reference pages carry no date. Treat the Guide as authoritative where it is explicit, and the reference as stale. Because the Guide has no date either, how recent each Guide-only feature is is not documented. The changelog does not mention any of them except "Function Tools in Responses API" (2026-02-05, https://docs.fireworks.ai/updates/changelog.md).

## 1. Endpoint, auth, request fields

- Endpoint: `POST https://api.fireworks.ai/inference/v1/responses`. Auth `Authorization: Bearer <API_KEY>`, body `application/json`. Required: `model`, `input`. (Guide, Create ref)
- The Spec's server is `https://api.fireworks.ai/inference` and the path `/v1/responses`. (Spec)

### Additional fields the Guide says are supported (not in the schema)

Guide, "Compatibility with OpenAI": "Supported request fields: `model`, `input`, `instructions`, `stream`, `store`, `previous_response_id`, `background`, `include`, `tools`, `tool_choice`, `parallel_tool_calls`, `max_tool_calls`, `max_output_tokens`, `metadata`, `reasoning`, `text`, `temperature`, `top_p`, `top_logprobs`, `truncation`, `user`, and `prompt_cache_key`." | Field               | What the Guide says                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

Not combinable with `stream` (400). Not every model supports it; unsupported models fail with `model_not_supported_for_background`. |
| `include`           | The only supported value is `message.output_text.logprobs`. | `top_logprobs`      | With `include=["message.output_text.logprobs"]`, logprobs attach to `output_text` content parts. | `prompt_cache_key`  | Listed as supported; semantics on this endpoint not documented. | `text.format`       | `{"type":"json_schema","name","strict","schema"}` and `{"type":"json_object"}` are supported. Example uses `strict: true`. | `stream`            | OpenAI Responses event vocabulary (`response.created`, `response.output_text.delta`, `response.web_search_call.*`, `response.reasoning_summary_text.*`, `response.completed`). ### OpenAI Responses fields not listed anywhere as supported

Not in the Guide's supported list, and not in the schema. Whether they are rejected (400/422) or silently ignored is **not documented**:

`conversation`, `context_management`, `service_tier`, `prompt_cache_options`, `prompt_cache_retention`, `safety_identifier`, `stream_options`, `prompt` (stored prompt templates). Also not listed: `text.verbosity`, `reasoning.generate_summary`, `include` values `reasoning.encrypted_content`, `file_search_call.results`, `web_search_call.action.sources`, `message.input_image.image_url`, `computer_call_output.output.image_url`, `code_interpreter_call.outputs`.

`service_tier`: for chat completions, `priority` is selected via `service_tier: "priority"` (https://docs.fireworks.ai/serverless/overview.md). The Responses guide does not list `service_tier`, so priority tier on `/responses` is not documented.

## 2. State, storage, retention

| Topic                                                     | Documented behaviour                                                                                                                                                                                                                                                                                      | Source                                                      |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `store` default                                           | `true`                                                                                                                                                                                                                                                                                                    | Spec, Guide                                                 |
| `store: false`                                            | Response is not persisted or retrievable. Response `id` is null ("Will be None if store=False"). Cannot be referenced by `previous_response_id`; caller must pass prior turns in `input`.                                                                                                                 | Spec, Guide                                                 |
| Retention                                                 | 30 days, then automatically deleted. Stores user prompts, model responses and tools called by the model.                                                                                                                                                                                                  | Data handling; Spec description "(Data retention: 30 days)" |
| Immediate deletion                                        | `DELETE /v1/responses/{response_id}`: "gone immediately and permanently"; later requests referencing that ID cannot access it. Returns `{"message": "Response deleted successfully"}` (`DeleteResponse.message`).                                                                                         | Delete ref, Spec                                            |
| Get                                                       | `GET /v1/responses/{response_id}` returns a `Response`. Error for unknown/expired ID not documented.                                                                                                                                                                                                      | Spec                                                        |
| List                                                      | `GET /v1/responses?limit=&after=&before=`. Default `limit` 20, max 100 (in prose; the schema has no max). Returns `{object:"list", data:[Response], has_more, first_id, last_id}`, newest first; `last_id` is the `after` cursor for the next page. Scope: "all responses for the authenticated account". | Spec                                                        |
| `input_items` list                                        | `GET /v1/responses/{id}/input_items` not supported.                                                                                                                                                                                                                                                       | Guide                                                       |
| Cancel                                                    | `POST /v1/responses/{id}/cancel` exists (background only). Not in the OpenAPI.                                                                                                                                                                                                                            | Guide                                                       |
| `conversation` object                                     | Not documented; no conversations endpoint is documented.                                                                                                                                                                                                                                                  | -                                                           |
| Zero Data Retention (Enterprise, account-wide, admin-set) | With ZDR enforced: `store: true` (the default) is **rejected**; `store: false` is allowed; `background: true` is rejected. Existing stored data is not deleted when the policy is turned on.                                                                                                              | ZDR                                                         |
| Data sent to MCP servers / web search                     | Handled under third parties' own policies.                                                                                                                                                                                                                                                                | ZDR                                                         |

### `previous_response_id` semantics

- Documented only as: "The ID of a previous response to continue the conversation from. When provided, the conversation history from that response will be automatically loaded." (Spec). The Guide: "you can continue a conversation by referencing the previous response instead of resending the full history."
- **Not documented**: whether `instructions`, `tools`, `tool_choice`, `reasoning`, `text`, `model` or other settings are inherited or must be resent; whether the whole chain (not just the immediate parent) is loaded; what happens with an unknown/expired/deleted/`store:false` ID (error status and code); whether forking from a non-latest response is allowed; whether reasoning items from earlier turns are carried into the next prompt; whether changing `model` between turns is allowed; whether the response `id` stored includes an in-flight `function_call` state when the next request supplies `function_call_output`.
- The response echoes `previous_response_id` (Spec).
- The cookbook "Continuing conversations" exists (https://github.com/fw-ai/cookbook/blob/main/archived/learn/response-api/fireworks_previous_response_cookbook.ipynb) but was not read; the Guide marks the cookbook folder as `archived`.

| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| String `input`                                  | Accepted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Message roles                                   | The Message schema says role "Can be 'user', 'assistant', or 'system'." `developer` role: **not documented**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Content part types                              | `MessageContent.type`: "for example `input_text`, `output_text`, `image`", with only a `text` field defined. `input_image` (URL or base64 data URL), `input_file`, `image_url`/`detail`: **not documented** in the Responses docs. (Image/vision input for chat completions is documented elsewhere; applicability to `/responses` is not.)                                                                                                                                                                                                                                          |
| `function_call` / `function_call_output` replay | Guide: client-executed `function` tools come back as `function_call` items; "You run them and send the results back." | `reasoning` items in input                      | Not documented.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `item_reference`                                | Not documented.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

| `mcp_call`, `web_search_call` in input          | Not documented.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Namespaced function calls in input              | Guide: Fireworks splits a flattened call back into `{namespace, name}` in the response "so Codex can dispatch it"; replaying them is not described.                                                                                                                                                                                                                                                                                                                                                                                                                                  |

## 5. Tools

| Tool                                                  | Documentation                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `function`                                            | Client-executed. Guide example: `{type:"function", name, description, parameters}` (flat, Responses-style, not nested under `function`). `strict` on function tools: **not documented**. `max_tool_calls` caps total calls per response. `defer_loading` has no effect (deferred tools exposed eagerly; no tool-search protocol).                                                                                 |
| `mcp`                                                 | Server-executed. Guide shows `{type:"mcp", server_url}` only. Fireworks discovers tools, calls them, feeds results back. Output as `mcp_call` items. `server_label`, `headers`, `authorization`, `allowed_tools`, `require_approval`, `server_description`, connectors: **not documented**. How secrets are stored/forwarded: not documented (the ZDR page says data sent to MCP servers follows their policies). |
| `sse`                                                 | `{type:"sse", server_url}` for MCP servers using the SSE transport. Fireworks-only.                                                                                                                                                                                                                                                                                                                               |
| `web_search`                                          | `{type:"web_search"}`. Server-executed. "Web search must be enabled for your account. If it is not, the request fails with a `403`." No options (`search_context_size`, `user_location`, `filters`) documented.                                                                                                                                                                                                   |
| `python`                                              | Named as server-executed in the Guide and Spec. Nothing else documented.                                                                                                                                                                                                                                                                                                                                          |
| `namespace` (Codex)                                   | `{type:"namespace", name, tools:[{type:"function",...}]}`. Fireworks flattens to `<namespace>__<tool>` for the model, and splits it back to `{namespace, name}` in `function_call` output. Nested entries must be `function` tools. Flattened names must be unique or the request is rejected. Reserved namespaces `multi_tool_use`, `functions`, `web`, `python` pass through unexpanded.                        |
| `custom` (freeform / grammar tools)                   | **Not documented.**                                                                                                                                                                                                                                                                                                                                                                                               |
| `code_interpreter`, `file_search`, `image_generation` | **Not supported** (Guide).                                                                                                                                                                                                                                                                                                                                                                                        |
| `computer`, `shell`, `apply_patch`, `tool_search`     | Not documented. `tool_search` explicitly has "no tool-search protocol here".                                                                                                                                                                                                                                                                                                                                      |
| `tool_choice`                                         | `none`, `auto`, `required`, or object naming a tool. The exact object shape (`{type:"function",name}`) is not shown. `allowed_tools` choice: not documented.                                                                                                                                                                                                                                                      |

| Auth                     | `Authorization: Bearer <FIREWORKS_API_KEY>` (https://docs.fireworks.ai/serverless/overview.md; Spec `BearerAuth`). No organization/project headers.                                                                                                                                                                                                                                                                                                                                                                                      |
| Error body               | Guide: OpenAI Responses envelope `{"error":{"type","code","message","param"}}`, example `type: "invalid_request_error"`, `code: "model_not_supported_for_background"`.                                                                                                                                                                                                                                                                                                                                                                   |
| 422 validation           | Spec: `{"detail":[{"loc":[...],"msg","type"}]}` (FastAPI-style `HTTPValidationError`). Conflicts with the Guide's envelope; which one applies to which failures is not documented.                                                                                                                                                                                                                                                                                                                                                       |
| Status codes             | "Status codes are preserved from the underlying inference call, so a `429` stays a `429`." (Guide). Shared table (https://docs.fireworks.ai/guides/inference-error-codes.md): 400, 401, 402 (payment/plan), 403, 404 (endpoint or model not found/not deployed/no permission), 405, 408, 412 (account suspended; LoRA failed to load), 413, 429, 500, 502, 503, 504, 520. Serverless load shedding is 503 "Service Overloaded" (https://docs.fireworks.ai/serverless/rate-limits.md). Deployments scaled to zero return 503 (changelog). |
| Responses-specific       | 403 when `web_search` is not enabled for the account; 404 "Model not found, inaccessible, and/or not deployed" for a model that is not a full resource name or not deployed; 400 for `background` + `stream`; `model_not_supported_for_background`.                                                                                                                                                                                                                                                                                      |
| Errors inside a response | In streaming and background requests the error is "embedded in the response object or emitted as an SSE error event" (Guide). For plain non-streaming requests a failure is an HTTP error; a `status: "failed"` with `error` in a 200 body is possible per the schema, but when it occurs is not documented.                                                                                                                                                                                                                             |
| Rate-limit headers       | Serverless responses: `X-Ratelimit-Limit-Tokens-Prompt`, `X-Ratelimit-Limit-Tokens-Cache-Adjusted-Prompt`, `X-Ratelimit-Limit-Tokens-Generated` (limits in tokens per minute) and `fireworks-prompt-tokens`, `fireworks-cached-prompt-tokens` (https://docs.fireworks.ai/serverless/overview.md). Documented for serverless inference generally; presence on `/responses` not stated. No `Retry-After`, `x-ratelimit-remaining`, or reset headers documented.                                                                            |
| Request ID header        | **Not documented.** The errors page only suggests logging "request IDs".                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Rate limits              | Per account and per model; adaptive TPM; dedicated deployments have no account-level limits and return 429 when saturated (https://docs.fireworks.ai/serverless/rate-limits.md, Errors page).                                                                                                                                                                                                                                                                                                                                            |

## 8. Model IDs and availability

- Format: `accounts/<ACCOUNT_ID>/models/<MODEL_ID>`, e.g. `accounts/fireworks/models/qwen3-235b-a22b` (Guide, Spec). Using anything that is not a full resource name gives 404 (Guide troubleshooting).
- Dedicated deployments use `accounts/<ACCOUNT_ID>/deployments/<DEPLOYMENT_ID>` "with the same APIs" (https://docs.fireworks.ai/guides/querying-text-models.md). The page names chat completions as the example and lists the Responses API as an alternative query method. The `model#accounts/.../deployments/...` form is **not documented** for Responses.
- Fast and router variants use `accounts/fireworks/routers/<name>` IDs (https://docs.fireworks.ai/serverless/overview.md); support on `/responses` not documented.
- Which models support the Responses API: **not documented**. Only the background mode has a stated model restriction ("Not every model supports background mode"). The Guide implies serverless and dedicated models in general; there is no support matrix, no list of reasoning/tool-capable models, no context-length or input-size limit specific to this endpoint.
- FireRouter IDs (`firerouter`, `firerouter/...`) are used by Codex over Responses (https://docs.fireworks.ai/nexus/harness-compatibility.md); behaviour details not documented here.

## Differences from OpenAI Responses

| Area                    | OpenAI                                                                                                         | Fireworks (as documented)                                                                                                     |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Request surface         | Large (`conversation`, `context_management`, `service_tier`, `prompt_cache_options`, `safety_identifier`, ...) | Only the listed fields (section 1). Anything else: undocumented behaviour.                                                    |
| `include`               | Many values                                                                                                    | Only `message.output_text.logprobs`. No `reasoning.encrypted_content`.                                                        |
| Reasoning               | `reasoning.effort`/`summary`, encrypted_content, `reasoning_text` content                                      | `reasoning.effort` only; summary always on; reasoning items with `summary_text`. Encrypted content not documented.            |
| Hosted tools            | web_search, file_search, code_interpreter, image_generation, computer, shell, apply_patch, tool_search, MCP    | `mcp`, `sse`, `web_search` (account-gated, 403), `python`; `code_interpreter`, `file_search`, `image_generation` unsupported. |
| MCP                     | `server_label`, `authorization`, `headers`, `allowed_tools`, `require_approval`, connectors, approval items    | Only `server_url` documented. No approval flow documented.                                                                    |
| `previous_response_id`  | Chain loaded; instructions/tools not inherited (documented)                                                    | History loaded; inheritance undocumented.                                                                                     |
| `store`                 | Default true, 30 days                                                                                          | Default true, 30 days; ZDR accounts reject `store:true`.                                                                      |
| Usage                   | `input_tokens`, `output_tokens`, `*_details`                                                                   | Spec says `prompt_tokens`, `completion_tokens`, `total_tokens`.                                                               |
| Error envelope          | `{error:{message,type,param,code}}`                                                                            | Same envelope per Guide; 422 uses FastAPI `detail[]` per Spec.                                                                |
| Extra endpoints         | GET, DELETE, cancel, `input_items`, `compact`                                                                  | GET, DELETE, LIST (extension), cancel (Guide). No `input_items`.                                                              |
| Refusals                | `refusal` content parts                                                                                        | Not supported.                                                                                                                |
| Roles                   | system, developer, user, assistant                                                                             | `developer` not documented.                                                                                                   |
| Message `phase`         | `commentary`/`final_answer`                                                                                    | Not documented.                                                                                                               |
| Model IDs               | `gpt-...`                                                                                                      | `accounts/<acct>/models/<id>`; deployments via `accounts/<acct>/deployments/<id>`.                                            |
| Headers                 | `OpenAI-Organization`, `OpenAI-Project`, `x-request-id`, `x-ratelimit-*`                                       | Bearer only; `X-Ratelimit-Limit-Tokens-*` and `fireworks-*` headers; request ID header not documented.                        |
| Codex `namespace` tools | Tool-search-related `namespace`                                                                                | Fireworks flattens `<ns>__<tool>` and splits back.                                                                            |

### What this implies for a base adapter plus Fireworks profile

- The profile's system role should probably be `system` (the schema lists system but not developer); confirm by live probe.
- Treat `usage` mapping as profile-specific: accept both `input_tokens`/`output_tokens` and `prompt_tokens`/`completion_tokens`.
- Do not assume `reasoning.encrypted_content` or the `include` list; replay reasoning items verbatim and verify they are accepted.
- `store: false` responses have `id: null`, so a stateless gateway cannot use `previous_response_id` unless `store` is true; ZDR accounts must use `store: false`.
- `background`, `stream` and `/cancel` are out of scope, but the response `status` enum should still allow `queued` and `cancelling`.
- MCP and `web_search` tools pass through `providerOptions.tools`; the documented MCP surface is only `server_url`.
- Error parsing needs to handle both the `error` envelope and the 422 `detail[]` shape.

## Not documented / unclear

Needs live probing (another agent is doing this) or Fireworks confirmation:

1. Whether unknown request fields (e.g. `service_tier`, `conversation`, `context_management`, `prompt_cache_options`, `include` values other than logprobs) are rejected or ignored.
2. What `previous_response_id` inherits (instructions, tools, tool_choice, reasoning, text), whether the full chain loads, error code for unknown/expired/deleted/`store:false` IDs, whether the model may change.
3. Exact `usage` shape on `/responses`, including cached tokens and reasoning tokens.
4. Reasoning item shape beyond `summary_text`: `content`/`reasoning_text`, `encrypted_content`, `id`, `status`; whether reasoning items are accepted when replayed, and whether they are needed for interleaved thinking; the meaning of the top-level `reasoning` response field.
5. Allowed values for `reasoning.effort` on `/responses`; whether `reasoning_effort`, `thinking`, `prompt_cache_isolation_key`, `perf_metrics_in_response`, `raw_output`, `response_format` are accepted there.
6. Input item union: `developer` role, `input_image` (URL/base64/`detail`), `input_file`, `item_reference`, `reasoning`/`mcp_call`/`web_search_call` replay, `custom_tool_call`, and the exact `function_call_output` shape (`call_id` vs `tool_call_id`).
7. Message `phase`, `annotations`, `logprobs` shapes; `refusal` handling.
8. Function tool `strict`; `tool_choice` object shapes; `custom` tools.
9. MCP tool fields beyond `server_url` (`server_label`, `headers`, `authorization`, `allowed_tools`, `require_approval`); `mcp_list_tools` and `mcp_approval_request` items; shape of `mcp_call`; credential handling.
10. `web_search` options and `web_search_call` fields; the `python` tool.
11. Which models support the Responses API; the `model#accounts/.../deployments/...` form; per-model limits; `metadata` value constraints; input size limits.
12. Request ID response header; `Retry-After`; whether `X-Ratelimit-*` and `fireworks-*` headers are sent on `/responses`; which errors use which envelope.
13. Release dates for the Guide-only features (background, include, namespace tools, `prompt_cache_key`, `web_search`); the OpenAPI reference does not have them, so the reference may be regenerated at any time.
14. `GET`/`DELETE` behaviour for unknown IDs (status code, body) and whether list returns only the caller's key or the whole account (Spec says account).
